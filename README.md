# Serial screening CT body composition before lung cancer diagnosis

Analysis code for the NLST study of paraspinal muscle ageing, bone attenuation and lung density before lung cancer diagnosis. This repository is a code snapshot prepared from the 2026-10-19 submission package.

The package contains the image-processing, statistical-analysis and figure-generation source code, the historical analysis plans, and their original SHA-256 records. Participant-level measurements, image data, segmentation masks, QC decisions and generated statistical outputs were not present in the supplied code snapshot and are not included here. The package has not been rerun end to end during preparation.

## Data preparation

The original analysis used the public NLST collection in the NCI Imaging Data Commons (IDC), release v24, and its public `nlst_prsn`, `nlst_canc` and `nlst_screen` clinical tables. The source code's clinical-table loader expects Parquet tables under `~/.local/share/IDC/v24/clinical_data/` (see `pipeline/nlst_select_download.py`, `CLIN`). Prepare that IDC clinical-data cache before selection. This folder is not supplied by the repository.

The analysis additionally reads `data/nlst/nlst_prsn_public.csv`; export the matching public `nlst_prsn` table to that location before the R analysis. The image downloader reads `data/nlst/nlst_selected_series_last.csv` to identify series shared with the related study. That manifest can be generated by running `pipeline/nlst_select_download.py --out data/nlst --rounds last`. The original downloader expects matching reusable NIfTI files and segmentations for series in that manifest; a fresh reconstruction must also prepare those cached files or adapt the download stage to fetch them. The source code has been retained without changing this reuse logic.

Images are obtained through `idc-index`; `dcm2niix` is required for conversion. In the original scripts, the `dcm2niix` executable is expected alongside the Python executable. Large images, cached tables, environments, weights and logs are excluded by `.gitignore`.

## Execution order

The original workflow uses Linux/Bash and SLURM for the heavy image-processing steps. Run commands from the repository root. The resource requests in the `.sbatch` examples should be adapted to the destination cluster.

Create `logs/`, `data/nlst/`, `data/nlst_serial/` and `results/p2/` before running or submitting jobs. The SLURM log directory must exist before `sbatch` opens its output file. The example jobs expect a Python environment at `env/bin/python`. `P2_PROJECT_ROOT` can override the project working directory; when it is unset, SLURM scripts use the submission directory and the statistics wrapper resolves the repository root from its own location.

1. **Selection.** Prepare the public tables and select the two case series:
   ```bash
   python pipeline/p2_select_serial.py --out data/nlst_serial
   python pipeline/p2_select_serial.py --out data/nlst_serial --scope unresected --prefix p2b --exclude-controls data/nlst_serial/p2_controls.csv
   ```
   `pipeline/p2_flow_counts.py` produces flow counts. `pipeline/p2_resample_riskset.py` prepares the alternative-control sensitivity analysis. The historical filename is retained; its eligible pool is restricted to participants never diagnosed with lung cancer, so it should not be read as unrestricted incidence-density sampling.
2. **Images.** After preparing the related-study cache described above, run `pipeline/p2_fetch_serial.py` for the `p2_series.csv` and `p2b_series.csv` manifests. The downloader and segmentation workers share the `data/nlst_serial/nifti/` and `data/seg/nlst_serial/` folders. The download log must contain `FETCH DONE` for workers to terminate. `pipeline/p2_fix_zero_spacing.py` repairs duplicated slice positions.
3. **Segmentation.** `pipeline/p2_segment.sbatch` invokes `pipeline/p2_segment_worker.py` for the TotalSegmentator `total`, `abdominal_muscles` and `body` tasks. `pipeline/p2_release_stale_locks.py` supports interrupted jobs.
4. **Measurement.** Use `pipeline/p2_metrics.py` directly or the sharded job examples. `pipeline/p2_metrics_merge.py` merges shard output into `results/p2/p2_paraspinal.csv`.
5. **QC.** Run `pipeline/p2_qc.py` and the montage/sheet helpers, then complete the visual-review step. Decisions and exclusion reasons are stored in `results/p2/p2_qc_review.csv`. The final review table is needed to reproduce the original exclusions; it is not included in this snapshot. A later blinded radiologist review may change the final analysis inputs.
6. **Field of view and maps.** Run `pipeline/p2_fov_truncation.py`, `pipeline/p2_maps.py` and `stats/p2_map_stats.py`.
7. **Statistics.** Use `stats/p2_run_all.sh` for the main Part A analysis and its six sensitivity runs. Then run `stats/p2_extra.R`, `stats/p2_phenotype.R`, `stats/p2_review_sens.R`, `stats/p2_bodysize_sens.R`, `stats/p2_power.py`, `stats/p2_extra_panels.py` and `stats/p2_table1.py` with the required intermediate inputs.
   The review sensitivities also require Part A runs into `results/p2/sens_riskset/` and `results/p2/sens_novisualqc/`; see the comments in `stats/p2_partA.R` and `docs/paper2/P2_04_review_sensitivity_prespec.md` for their input definitions.
8. **3D assets.** `figures/p2_render3d.py`, `figures/p2_render_maps3d.py` and `figures/p2_render_reserve3d.py` create assets under `figures/assets/`. The original renders used a separate VTK 9.7.0 environment with EGL.
9. **Figures.** Run `figures/p2_figs_main.py`, `figures/p2_figs_pheno.py`, `figures/p2_figs_ed.py` and `figures/p2_figs_adv.py`. Outputs go to `figures/p2/out/` unless overridden by the existing environment settings.

Supplementary figure mapping: S1-S3 and S6 use `p2_figs_ed.py`; S4, S5, S7 and S8 use `p2_figs_main.py`; S10 is its `fig5` function; S9, S11 and S12 use `p2_figs_adv.py`.

## Analysis-plan provenance

The three subsequent analysis-plan files and their hash records were copied byte for byte. The SHA-256 matches were verified when this package was prepared. Locally recorded timestamps do not establish independent preregistration. The reserve-score plan was written after component-level case-control differences were known; that analysis is exploratory. The original planning documents are retained as historical records, including their dated amendments.

## Reproduction status

This upload package provides source code. Numerical reproduction requires public image/table preparation, the original or updated QC decisions, and generated intermediate results. In particular, the per-scan measurements mentioned in the manuscript's draft data-availability statement are not included in the materials available for packaging. The statement should describe only files that are actually released.

No manuscript results, cohort definitions, analysis models or historical hashed plans were changed when making this package. Changes to existing executable files are limited to working-directory and log-path configuration in the six shell/SLURM examples; details are in `PACKAGE_NOTES.md`.
